2. Gargalo de Contenção Atômica nos 10 Crivos Diagonais (Kernel Time @ 16M)

Portar ingenuamente sector_mass[d] += val com atomicAdd global faz 2.560 threads colidirem nos mesmos 10 endereços!

K1: Naive Global atomicAdd nos 10 Crivos (Serialização L2: 2.25 GB/s)28.45 ms
K0: Dense Baseline na GPU (1,024 Bilhão de MULs)14.82 ms
K2: Shared Memory atomicAdd (Conflito de 10 Bancos: 20.51 GB/s)3.12 ms
K3: GNC-X Warp-Shuffle __shfl_down_sync + Padded [8][16] (224.39 GB/s)0.285 ms (52x mais rápido que K0!)
Veredito Arquitetural para GPU (CUDA):
1. Proibido usar atomicAdd direto nas 10 diagonais: Como todas as threads convergem para apenas 10 pivôs D(k, 0..9), o hardware serializa os Warps. A redução precisa ocorrer em registradores + __shfl_down_sync intra-warp + Shared Memory com padding [WARPS][16].
2. Tensores 4-Phase devem residir na VRAM: Como o Kernel K3 processa 16M elementos em 0,285 ms (224,5 GB/s efetivos), os dados devem permanecer em VRAM entre camadas (evitando round-trips PCIe).
